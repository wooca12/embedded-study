02 / MAKE IT WORK

보드 실습 ① · HAL로 LED 깜빡이기

  1. NUCLEO-F103RB와 데이터 통신 가능한 Mini-USB 케이블을 준비해요.
  2. CubeIDE 1.19.0에서 STM32 프로젝트를 만들고 Board Selector에서 NUCLEO-F103RB를 선택해요.
  3. PA5가 GPIO Output, Push-Pull인지 확인하고 코드를 생성해요. GPIOA 클럭과 핀 초기화 코드를 확인하세요.
  4. 초기화 이후 반복문의 USER CODE 영역에 아래 코드를 넣어요.
  5. 빌드 → ST-LINK로 다운로드·실행 → LD2가 0.5초마다 바뀌는지 관찰해요.
HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
HAL_Delay(500);

예상해보기: 켜짐 0.5초 + 꺼짐 0.5초라면 한 주기는 몇 초일까요? 500을 100으로 바꾸면 어떻게 될까요?

동작하지 않을 때 확인할 것

전원 → 데이터 케이블 → ST-LINK 인식 → 보드 선택 → PA5 출력 모드 → GPIOA 클럭 → 코드 다운로드 → 실행 재개 순서로 확인하세요. 디버거가 브레이크포인트에서 멈춰 있으면 LED도 갱신되지 않아요.

보드 실습 ② · 버튼 상태 읽기

PC13을 입력으로 설정하고 보드 회로에 맞는 풀업 구성을 확인해요. 표준 NUCLEO-F103RB B1은 눌렀을 때 LOW인 active-low 입력입니다. 생성한 GPIO 초기화 이후 반복문에서 실행하세요.

GPIO_PinState pressed = HAL_GPIO_ReadPin(GPIOC, GPIO_PIN_13);
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5,
    pressed == GPIO_PIN_RESET ? GPIO_PIN_SET : GPIO_PIN_RESET);

버튼을 누르는 동안 LD2가 켜지는지 확인해요. 눌렀을 때 1이라고 가정하면 왜 반대로 동작할까요? 한 번 눌러 한 번 토글하려면 상태 변화 감지와 디바운싱을 추가로 배워야 합니다.

강의 실습 · PDF p.119–136

UART 송신·수신 확인하기

  1. USART2를 Asynchronous로 설정하고 PA2 TX·PA3 RX, Baud Rate 115200을 확인해요.
  2. 코드 생성 후 UART 초기화 함수가 main에서 호출되는지 확인해요.
  3. 학습 카드의 HAL_UART_Transmit 예제로 문자열을 보내요.
  4. PC 터미널에서 보드 포트와 115200·8N1 설정을 맞춰요. 실제 프로젝트 설정과 일치해야 합니다.
  5. HAL_UART_Receive 결과가 HAL_OK일 때만 받은 한 바이트를 다시 보내는 에코 실습을 해요.
Mac에서 포트 찾기 · 보충

터미널의 ls /dev/cu.* 결과를 보드 연결 전후로 비교해요. 시리얼 터미널에서는 새로 나타난 보드 포트를 선택합니다. 강의의 Windows COM 번호나 MobaXterm 화면을 Mac에 그대로 적용하지 않아요.

관찰: 보드 초기화·포트 선택·통신 속도·실행 재개를 확인하고, 받은 문자가 두 번 보이면 로컬 에코 설정과 펌웨어 에코가 중복인지 확인해요.

printf·scanf 연결 확인하기

강의 순서대로 syscalls.c의 weak _write/_read를 확인하고 UART로 연결합니다. 아래는 연결 원리를 확인하기 위한 새 학습 예제입니다. 생성된 함수 시그니처와 맞춰 중복 정의를 피하고, UART 초기화 뒤에 호출하세요.

// main.c 등의 USER CODE 함수 영역: stdio.h / errno.h 포함 필요
int _write(int file, char *ptr, int len) {
  (void)file;
  if (len <= 0) return 0;
  if (HAL_UART_Transmit(&huart2, (uint8_t *)ptr, len, 1000) != HAL_OK) {
    errno = EIO;
    return -1;
  }
  return len;
}
int _read(int file, char *ptr, int len) {
  (void)file;
  if (len <= 0) return 0;
  if (HAL_UART_Receive(&huart2, (uint8_t *)ptr, 1, HAL_MAX_DELAY) != HAL_OK) {
    errno = EIO;
    return -1;
  }
  return 1;
}

예: UART 초기화 뒤 printf("ready\r\n");를 출력하고 정수 입력은 scanf("%d", &value)의 반환값이 1인지 확인하세요. _read는 입력까지 기다리는 예시이며 입력 에코는 포함하지 않았어요. 출력 버퍼링에 따라 줄바꿈·fflush(stdout) 확인이 필요할 수 있습니다.

관찰: HAL 전송은 되는데 printf는 안 되는지, 엔터 전후 scanf가 언제 완료되는지 비교해요. 이 예제는 실기 빌드·동작 미검증입니다.

보충 실습 · HAL과 레지스터 연결하기

위 실습에서 초기화한 PA5를 그대로 사용해요. 켜는 동작과 끄는 동작을 아래처럼 바꾸어 봐요.

GPIOA->BSRR = (1u << 5);   // PA5 SET
HAL_Delay(500);
GPIOA->BSRR = (1u << 21);  // PA5 RESET: 16 + 5
HAL_Delay(500);

ENVIRONMENT / MAC M1

개발 환경 준비

STM32CubeIDE 1.19.0 · 설치 안내

M1은 Rosetta를 통한 실행 경로가 있습니다. 다만 1.19.0 공식 지원 OS 안내는 macOS 14·15이며, 확인한 이 Mac은 26.4.1입니다. 현재 환경에서 실행·빌드·디버깅이 되는지는 별도 확인해야 해요.

  1. ST 공식 다운로드 페이지의 Get Software로 이동해요.
  2. 운영체제는 macOS (Intel), 버전은 1.19.0을 선택해요. 최신 Apple Silicon 설치 파일과 혼동하지 마세요.
  3. 라이선스 확인 및 ST 로그인/이메일 인증 후 설치 파일을 다운로드해요.
  4. 설치 중 Rosetta 안내가 나오면 macOS 안내를 따라 설치해요. ST Link Server 설치 후 IDE를 Applications에 배치해요.
  5. 영문 경로에 workspace를 만들고 NUCLEO-F103RB 프로젝트를 생성해요. STM32CubeF1 패키지 다운로드가 필요할 수 있어요.
  6. IDE 실행 → 프로젝트 빌드 → ST-LINK 인식 → LED 예제 다운로드·실행 순서로 확인해요.

1.19.0이 현재 macOS에서 동작하지 않으면 오류 메시지를 기록하세요. 스터디에서 버전 차이를 허용하는지 확인한 뒤, 공식 Apple Silicon 버전을 대안으로 검토하면 됩니다. 이 안내는 설치 완료를 의미하지 않습니다.
